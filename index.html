The Mental Model — It's Just a Server, Differently Shaped

You already know how to think about complex systems. 3D is just another system. Here's your Rosetta Stone.

The Scene is your database. Everything lives in it — objects, lights, cameras. It's the root container for your entire 3D world.

Lights illuminate the scene. No light = everything is pitch black (or flat, no shadows). They set the "ambient" conditions your objects live in.

The render loop (engine.runRenderLoop) is your main event loop. It runs at 60fps, updating and re-drawing the scene every frame.

// 02

3D Space 101 — The Boring Maths You Actually Need

You can't avoid vectors. Sorry. But this is all of it — nothing more is required to get productive.

Concept
What it means

Vector3(x, y, z)

A point in 3D space OR a direction. Think of it like coordinates(lat, lng, altitude). X = left/right. Y = up/down. Z = forward/back. That's it.

position

Where the mesh is in the world. mesh.position = new Vector3(0, 1, 5) puts it at x=0, y=1 (1 unit up), z=5 (5 units forward).

rotation

How it's rotated, in radians. mesh.rotation.y = Math.PI / 2 rotates it 90° around the Y axis (spins left/right). Use Tools.ToRadians(90) if you hate radians.

scaling

How big it is. mesh.scaling = new Vector3(2, 2, 2) makes it 2x larger in all directions. Like CSS transform: scale().

parent

mesh.parent = otherMesh makes position/rotation relative to parent. Like CSS position: relative inside a container. Move the parent, children follow.

World vs Local space

"World" = absolute position in the scene. "Local" = relative to the object's own orientation. When an object is rotated, its local axes rotate with it.

⚠️

// GOTCHA: Y-up vs Z-up

Babylon.js uses a left-handed, Y-up coordinate system. Y is up. Z goes INTO the screen (away from you). If you import assets from Blender (Z-up), you may need to rotate them. This trips everyone up.

babylon.js // vectors
// Think of Vector3 like a struct/tuple with x, y, z
const pos = new BABYLON.Vector3(0, 5, 10);

// Move a mesh
mesh.position.x += 0.1;          // move right a bit
mesh.position = BABYLON.Vector3.Zero(); // reset to origin

// Rotate (radians, not degrees!)
mesh.rotation.y = BABYLON.Tools.ToRadians(45); // 45°

// Scale uniformly
mesh.scaling = new BABYLON.Vector3(2, 2, 2);

babylon.js // minimal setup
// index.html — just needs a canvas
// <canvas id="renderCanvas"></canvas>

const canvas = document.getElementById("renderCanvas");

// Engine = the WebGL context manager. antialias=true for smoother edges
const engine = new BABYLON.Engine(canvas, true);

// Scene = your "database" — all objects registered here
const scene = new BABYLON.Scene(engine);

// Camera — ArcRotateCamera orbits around a target point (great default)
// params: name, alpha(h-rotation), beta(v-rotation), radius, target, scene
const camera = new BABYLON.ArcRotateCamera(
  "cam", -Math.PI/2, Math.PI/2.5, 10,
  BABYLON.Vector3.Zero(), scene
);
camera.attachControl(canvas, true); // enable mouse drag to orbit

// Light — HemisphericLight is the lazy default (ambient light from above)
const light = new BABYLON.HemisphericLight(
  "light", new BABYLON.Vector3(0, 1, 0), scene
);

// Create a box mesh (it auto-registers in the scene)
const box = BABYLON.MeshBuilder.CreateBox("box", { size: 2 }, scene);

// THE RENDER LOOP — runs ~60 times per second
engine.runRenderLoop(() => {
  scene.render();
});

// Resize when window resizes (like any canvas app)
window.addEventListener("resize", () => engine.resize());

Meshes — The 3D Objects You'll Actually Work With

MeshBuilder is your factory. It makes the common shapes so you don't have to think about geometry. Loading external models (glTF/glb) is how you get complex objects.

babylon.js // mesh builder
// Box — options object controls dimensions
const box = BABYLON.MeshBuilder.CreateBox("box", {
  width: 2, height: 1, depth: 3
}, scene);

// Sphere
const sphere = BABYLON.MeshBuilder.CreateSphere("sphere", {
  diameter: 2, segments: 32  // segments = smoothness
}, scene);

// Plane (flat quad — useful for floors, billboards)
const plane = BABYLON.MeshBuilder.CreatePlane("plane", {
  width: 10, height: 10
}, scene);

// Ground (like plane but horizontal by default, with subdivisions)
const ground = BABYLON.MeshBuilder.CreateGround("ground", {
  width: 20, height: 20, subdivisions: 2
}, scene);

// Cylinder (also makes cones)
const cyl = BABYLON.MeshBuilder.CreateCylinder("cyl", {
  height: 3, diameter: 1, tessellation: 16
}, scene);

// All meshes created at origin (0,0,0) — move them after
box.position.y = 2;
sphere.position = new BABYLON.Vector3(5, 1, 0);
babylon.js // load external models (gltf/glb)
// glTF is the "JPEG of 3D" — it's what you'll receive from designers
// .glb = binary (single file), .gltf = JSON + separate texture files

// Import a model — async/await style
const result = await BABYLON.SceneLoader.ImportMeshAsync(
  "",          // mesh names to load ("" = all)
  "/assets/", // folder path
  "robot.glb", // filename
  scene
);

// result.meshes = array of all loaded meshes
// result.animationGroups = animations baked into the file

const root = result.meshes[0]; // root node of the hierarchy
root.position.y = 0;
root.scaling = new BABYLON.Vector3(0.01, 0.01, 0.01); // scale down often needed

// Play a baked animation
const walkAnim = result.animationGroups.find(a => a.name === "Walk");
walkAnim.play(true); // true = loop
⚠️

// GOTCHA: CORS & file:// protocol

You cannot load .glb files from the filesystem directly (CORS). Run a local dev server (Vite, live-server, etc.). This is the #1 beginner frustration.

babylon.js // mesh manipulation
// Clone (deep copy — separate geometry)
const clone = mesh.clone("clone1");
clone.position.x = 5;

// Instance (same geometry, different transform — VERY fast for many copies)
// Like database views — reference the same data, transformed differently
const instance = mesh.createInstance("inst1");
instance.position.x = -5;

// Show/hide
mesh.isVisible = false;
mesh.setEnabled(false); // also disables physics/events

// Pick a mesh from mouse click
scene.onPointerDown = (evt, pickResult) => {
  if (pickResult.hit) {
    console.log("clicked:", pickResult.pickedMesh.name);
    pickResult.pickedMesh.material.diffuseColor = new BABYLON.Color3(1, 0, 0);
  }
};
// 05

Camera & Lights — Setting the Stage

Pick the right camera once and you're done. Lights are where you spend 20% of your time for 80% of the visual quality difference.

Camera Type
Use When

ArcRotateCamera

Most common

Orbits around a target point. Perfect for product viewers, character inspection, most 3D UIs. Mouse drag = orbit, scroll = zoom.

FreeCamera

WASD + mouse = FPS controls. Use for walkthroughs, first-person experiences. Needs camera.attachControl(canvas, true).

FollowCamera

Follows a mesh around. Set camera.lockedTarget = mesh. Great for third-person games or following animated objects.

UniversalCamera

FreeCamera + gamepad support. The "just make it work everywhere" camera. Good default if you're not sure.

babylon.js // lights reference
// 1. HemisphericLight — ambient, from a direction (sky/ground color)
//    No shadows. Great as fill light or sole light for simple scenes.
const hemi = new BABYLON.HemisphericLight(
  "hemi", new BABYLON.Vector3(0, 1, 0), scene
);
hemi.intensity = 0.7;

// 2. DirectionalLight — like the sun. Parallel rays, can cast shadows.
const dirLight = new BABYLON.DirectionalLight(
  "dir", new BABYLON.Vector3(-1, -2, -1), scene
);

// 3. PointLight — light bulb. Radiates in all directions from a point.
const point = new BABYLON.PointLight(
  "point", new BABYLON.Vector3(0, 5, 0), scene
);
point.diffuse = new BABYLON.Color3(1, 0.8, 0.5); // warm orange

// 4. SpotLight — cone of light. Like a stage spotlight.
const spot = new BABYLON.SpotLight(
  "spot",
  new BABYLON.Vector3(0, 10, 0),  // position
  new BABYLON.Vector3(0, -1, 0), // direction (downward)
  Math.PI / 4,  // angle (cone width in radians)
  2,            // exponent (edge softness)
  scene
);

// Add shadows to a DirectionalLight
const shadowGen = new BABYLON.ShadowGenerator(1024, dirLight);
shadowGen.addShadowCaster(box); // this mesh casts shadows
ground.receiveShadows = true; // this mesh receives shadows

Materials — Appearance is Everything

Materials define what an object looks like. Think of them as "styles" you assign to meshes. One material, many meshes.

babylon.js // standard material
// StandardMaterial — the bread-and-butter material
const mat = new BABYLON.StandardMaterial("mat", scene);

// diffuseColor = the base "lit" color (what you'd call background-color)
mat.diffuseColor = new BABYLON.Color3(0.4, 0.6, 1.0); // RGB 0-1

// emissiveColor = color that glows (not affected by lights)
mat.emissiveColor = new BABYLON.Color3(0.1, 0.1, 0.3);

// specularColor = shininess highlight color
mat.specularColor = new BABYLON.Color3(1, 1, 1);
mat.specularPower = 64; // higher = smaller, sharper highlight

// Transparency
mat.alpha = 0.5; // 0 = invisible, 1 = opaque

// Wireframe (great for debugging)
mat.wireframe = true;

// Assign to mesh
box.material = mat;

// ─────────────────────────────────────────────

// PBRMaterial — "Physically Based Rendering" — looks way more realistic
// Use this for modern, high-quality scenes
const pbr = new BABYLON.PBRMaterial("pbr", scene);
pbr.albedoColor = new BABYLON.Color3(0.8, 0.2, 0.1); // base color
pbr.metallic = 0.0;    // 0 = plastic, 1 = metal
pbr.roughness = 0.5;   // 0 = mirror, 1 = matte
sphere.material = pbr;
babylon.js // textures
// Textures are image files mapped onto mesh surfaces
const mat = new BABYLON.StandardMaterial("texMat", scene);

// diffuseTexture = the main color texture (image wrapped on the mesh)
mat.diffuseTexture = new BABYLON.Texture("/assets/wood.jpg", scene);

// Tile the texture (useful for floors/walls)
mat.diffuseTexture.uScale = 4; // repeat 4x horizontally
mat.diffuseTexture.vScale = 4; // repeat 4x vertically

// bumpTexture = normal map (fake surface detail without extra geometry)
mat.bumpTexture = new BABYLON.Texture("/assets/wood_normal.jpg", scene);

ground.material = mat;

Animation — Making Things Move

There are two ways to animate: the render loop (imperative, like writing your own setInterval) and Babylon's Animation system (declarative keyframes). Know both.

babylon.js // render loop animation (simple)
// The "just do it every frame" approach
// Like a game loop — runs 60x per second

let angle = 0;

engine.runRenderLoop(() => {
  angle += 0.01;

  box.rotation.y = angle;      // spin the box
  sphere.position.y = Math.sin(angle) * 2; // bob up/down

  scene.render();
});
babylon.js // keyframe animation system
// Define an animation: "position.y", 60fps, FLOAT type
const anim = new BABYLON.Animation(
  "myAnim",
  "position.y",           // property to animate (dot notation works!)
  60,                     // fps
  BABYLON.Animation.ANIMATIONTYPE_FLOAT,
  BABYLON.Animation.ANIMATIONLOOPMODE_CYCLE // or CONSTANT
);

// Set keyframes (like CSS @keyframes)
anim.setKeys([
  { frame: 0,  value: 0 },
  { frame: 30, value: 5 },
  { frame: 60, value: 0 }
]);

// Attach and play
box.animations.push(anim);
scene.beginAnimation(box, 0, 60, true); // (target, from, to, loop)

// ── Tweening with Animation.CreateAndStartAnimation ────────────────
// Quick one-liner to animate a property to a value over time
BABYLON.Animation.CreateAndStartAnimation(
  "move", box, "position.x", 60, 60,
  box.position.x, 10,     // from, to
  BABYLON.Animation.ANIMATIONLOOPMODE_CONSTANT
);
✅

// PRO TIP: Use scene.onBeforeRenderObservable for logic

Put game logic / state updates in scene.onBeforeRenderObservable.add(fn) rather than inside runRenderLoop. Keeps concerns separated — rendering in the loop, logic in the observable.

// 08

The Gotchas That Will Get You

Things that tripped up every backend dev who touched 3D. Read these now, save yourself hours later.

⚠️

// DISPOSE everything you create

Meshes, materials, textures — they all consume GPU memory. Call mesh.dispose(), material.dispose() when you're done with them. Unlike JS garbage collection, WebGL resources are NOT automatically freed. This is the #1 memory leak cause.

⚠️

// Babylon uses Left-Handed coordinate system

Z goes away from you (into the screen). This is opposite to OpenGL/WebGL defaults and some 3D tools like Blender (which are right-handed). When something is flipped or mirrored unexpectedly, this is probably why.

⚠️

// Don't create objects inside the render loop

new BABYLON.Mesh() inside runRenderLoop = new GPU allocation 60x per second. Your memory will explode. Create objects once, outside the loop. Only update properties inside it.

⚠️

// Color3 is 0–1, not 0–255

new BABYLON.Color3(1, 0, 0) = red. NOT Color3(255, 0, 0). Use Color3.FromHexString("#ff0000") or Color3.FromInts(255, 0, 0) if you think in 255-space.

⚠️

// Async loading pitfall

SceneLoader.ImportMeshAsync is async. If you try to reference the loaded mesh synchronously after calling it (without await), you'll get undefined. Always await it or use the callback.

⚠️

// Performance: draw calls

Each mesh = 1+ draw calls to the GPU. 500+ draw calls per frame = slow. Use mesh.createInstance() for repeated objects (trees, bullets, tiles). Use BABYLON.Mesh.MergeMeshes() to combine static geometry. Check the inspector (scene.debugLayer.show()) for draw call counts.

// Quick Cheat Sheet

  • Rotate: always in radians. 180° = Math.PI. 90° = Math.PI/2.
  • Nothing visible? Check you have a camera AND a light.
  • Black screen? HemisphericLight with intensity=1 is your emergency fix.
  • Object in wrong place? Log mesh.getAbsolutePosition() — parenting affects displayed position.
  • Texture not showing? Check CORS — you need a dev server.
  • Bad performance? Open the Babylon Inspector and check Draw Calls and Active Meshes.
  • Enable Inspector: scene.debugLayer.show() — it's like DevTools for your scene.
  • Model too big/small after import? Scale the root mesh, not individual children.
